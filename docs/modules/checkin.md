# 打卡簽到

複雜模組（判定見 [architecture.md](../architecture.md) §3）。這份只寫規則與驗收。

## 規則
- 觀眾在聊天室打 `!<指令>` 就算打卡：只看訊息的第一個詞，英文字母不分大小寫。指令（預設 `打卡`，存的時候不含 `!`）與誰能用（預設所有人）存在共用的聊天指令表（[architecture.md](../architecture.md)「聊天指令」）；名稱和其他功能的指令相同時拒絕存檔，並說明是誰在用。不能用的人打指令不算打卡，實況主本人永遠可以。
- 也可以在設定裡選一個頻道點數獎勵（存 Twitch 的獎勵 ID，清單向 Twitch 讀取）：觀眾兌換它就算打卡。打卡模組經 outbox 收到兌換紀錄的 `RedemptionRecorded`；沒有設定獎勵，或兌換的是其他獎勵，都不打卡。兌換被退還不會取消打卡。
- 同一筆兌換只打卡一次：處理過的事件 ID 記在 inbox，與打卡寫在同一個交易，重送也一樣。
- 同一個觀眾在同一個營運日只算一次，不論先用指令還是兌換。資料庫的唯一限制（觀眾＋營運日）也擋重複，不只靠程式判斷。
- 觀眾以 Twitch user ID 識別（改名不影響）；內部 ID 是 UUID v7，Twitch user ID 另存一欄。名稱存最新一次看到的。
- 模擬事件（`source=simulation`）不寫入打卡紀錄。
- 程式關著的時候收不到兌換（Twitch 的限制）；程式開著但還沒處理到的兌換，重啟後補上，營運日算兌換當下那天。
- 模組停用期間，聊天室的打卡指令直接丟棄，和其他記憶體事件一樣；已存的紀錄保留。
- 停用時選「暫停」或「關閉」（[architecture.md](../architecture.md) §4）：
  - 暫停：兌換留在 outbox，不累計重試；設定頁顯示累積幾筆與最舊的兌換時間；重新啟用後依序補打卡，營運日算兌換當下。
  - 關閉：選之前先警告；停用期間（含暫停時已累積）的兌換標為略過，重新啟用後不補。從暫停改為關閉時，已累積的一併略過。
- 一直處理失敗的兌換（共 5 次）移到失敗清單，不再擋住後面的兌換；設定頁列出，可以「重試」（重新計算次數）或「略過」。
- 時間存 UTC；事件的時間讀不懂時，改用收到的時間。

## 管理 UI
- 首頁「打卡」功能磚與抽屜顯示今天（目前的營運日）打卡的人數與最近幾位；完整頁列出觀眾的累計次數、集點卡與最後打卡日，可搜尋登入名稱或顯示名稱。
- 可以手動幫已知的觀眾登記今天，或補登過去的營運日（記在那天的開始時間）；不能登記未來的營運日。手動登記和補登遵守同一條「每個營運日一次」規則，重複時回傳「已經打過卡」並提示，不算錯誤。
- 觀眾名稱只當文字顯示。不提供刪除、修改單筆紀錄或匯出；累計次數不能修改。
- 完整頁每位觀眾另有「可用印章」，可以扣（例如集滿換一首點歌時按一下），原因選填；「異動紀錄」列出最近 100 次扣除（時間、觀眾、格數、原因）。見下方「印章」。

## OBS 集點卡
- `/overlay/checkin/`：打卡成功時顯示觀眾名稱、頭像和集點卡，剛好集滿時有不同的效果；同時很多人打卡時照順序一張一張顯示；當天重複打卡預設不顯示，卡片樣式可以選擇顯示（不寫紀錄；重送的兌換事件不會再顯示）。
- 卡片樣式（分頁「卡片樣式」）：內建樣式（簡約、手帳）、背景顏色或圖片、印章顏色或圖片、每排幾格、標題與說明文字（可用 `#觀眾#` `#章數#` `#次數#` `#格數#`，由 Host 代換，Overlay 只當文字顯示）、進場動畫。存檔後下一張卡片就用新樣式；「在 OBS 試播」用存好的樣式排一張測試卡，不寫紀錄。圖片只收 PNG、JPG、GIF、WebP（不收 SVG），副檔名與檔案開頭要一致，最多 5 MB，存在資料夾的 `checkin/`，隨備份一起備份與還原。
- 完整頁每一列可以「把集點卡推到畫面」（排進呈現佇列，不寫打卡紀錄）；頁首「隱藏畫面卡片」立刻收掉畫面上的卡片。
- 可以用抽屜的模擬器測試畫面，不寫入紀錄。細節見 [architecture.md](../architecture.md)「集點卡 Overlay」。

## 匯入
- 在完整頁選一個 JSON 檔：管理 UI 讀取檔案內容後送到 Host 預覽（會新增幾位、更新幾位、略過幾筆與原因），確認後才在同一個交易裡寫入。原始檔不會被修改。檔案最大 5 MB。
- 格式：一個以 Twitch user ID 為鍵的 JSON 物件，每一項可以有：
  - `totalCheckIns`（必填，0 到 1,000,000,000 的整數）：累計次數。
  - `lastName` 或 `name`：顯示名稱（兩者都有時用 `lastName`）；新觀眾的登入名稱要等他之後打卡才知道。
  - `profileImage`：頭像網址，只接受 Twitch 圖片 CDN，已有頭像時不覆蓋。
  - `lastCheckInDate`（`YYYY-MM-DD`）：最後打卡日，當成日期讀，不換算時區；沒有就留空。它不會擋住當天打卡。
  - `stamps`、`isOwner`、`excluded`；其他欄位一律忽略。
- 略過並列出原因：鍵不是數字、`isOwner` 或 `excluded` 為 `true`、`totalCheckIns` 缺少或不合法、`lastCheckInDate` 不是日期。
- 匯入的次數存成該觀眾的基準值，之後的匯入會覆蓋它，所以同一份檔案匯入兩次結果相同。顯示的累計次數＝基準值＋本工具記錄的打卡次數；集點卡由累計次數重新計算，不用檔案裡的 `stamps`；最後打卡日取基準日期與本工具紀錄中較晚的那天。
- 已知的觀眾保留目前的名稱。

```json
{
  "12345678": { "totalCheckIns": 23, "lastName": "觀眾名稱", "lastCheckInDate": "2026-10-31" },
  "87654321": { "totalCheckIns": 5, "name": "另一位", "excluded": true }
}
```

## 營運日
- 設定：時區（IANA，預設 `Asia/Taipei`）與換日時間（當地 0–23 點，預設 0 點）。
- 營運日由事件發生的時間（`occurredAt`）判斷，不用處理的時間：當地時間減去換日時間後的日期。例：換日時間 6 點時，11/17 凌晨 5 點仍算 11/16。
- 日光節約時間：換日時間在當地不存在（跳過的那一小時）時，從時鐘再次走到該時刻起算；重複的那一小時取第一次。
- 改時區或換日時間：觀眾這次打卡的營運日已有紀錄，或新設定下這個營運日的時間範圍內已有紀錄，都算重複。所以改設定當天不會多算；可能少算一次（舊紀錄的營運日標籤與新設定下的另一天相同時）。
- 設定檔裡無法使用的值逐項改用預設值；管理 API 拒絕不合法的值（`checkin.invalid_settings`）。

## 集點卡
- 不另外存，由累計次數算出：累計 0 次時 0 格；否則 `(累計 - 1) % 格數 + 1`。剛好集滿時顯示滿格，下一次打卡才開始新的一張。
- 格數是設定（1–100，預設 10）；改了之後所有觀眾的卡片立刻依新格數重新計算。

## 印章
- 可用印章＝累計次數－已扣格數，最少顯示 0。扣印章不影響累計次數，集點卡也照舊由累計次數計算。
- 每次扣 1 格以上，最多扣到可用印章歸零，不能扣成負數；扣超過時拒絕並說明目前還有幾格。扣除和打卡一樣一件一件依序處理，檢查與寫入在同一個交易，所以同時按兩次也不會扣成負數。
- 扣除存在 `checkin_deductions`（觀眾、格數、原因、時間），隨資料庫一起備份；不提供刪除或修改。
- 匯入讓累計次數低於已扣格數時，可用印章顯示 0，異動紀錄照舊保留。
- 集滿自動換點歌不做（先手動）。

## 驗收
- 同一個營運日重複打卡不會多算；營運日依設定的時區和換日時間、用事件發生的時間判斷。
- 改了時區或換日時間之後，當天已經打過卡的觀眾不會因此多算一次。
- 同一筆兌換只打卡一次（重送也一樣）；同一天先用指令、再用兌換打卡，只算一次；補送的兌換依兌換當下的時間算營運日。
- 暫停後重新啟用，期間的兌換照順序補上，日期算兌換當下；關閉後重新啟用，期間的兌換不補。
- 重試超過上限的事件移到失敗清單，不會卡住後面的事件。
- 手動登記和補登一樣遵守「每個營運日一次」，重複時會提示，不會多算；改了集點卡格數，所有觀眾的卡片立刻重新計算。
- 匯入：原始檔內容不變；用 Twitch user ID 比對觀眾，重複匯入同一份資料不會重複累加；略過的項目在預覽裡列出原因；集點卡從 `totalCheckIns` 重新計算；有 `lastCheckInDate` 就當成最後打卡日，沒有就留空，當天照樣可以打卡。
- 模擬事件不寫入打卡紀錄；模組停用期間不產生紀錄。
- 扣印章：不會扣成負數（同時扣兩次也一樣）；不影響累計次數與集點卡；匯入讓累計低於已扣格數時可用印章顯示 0，異動紀錄保留。
- 以上都有測試（Repository 用真 SQLite）。
