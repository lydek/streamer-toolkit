# 兌換紀錄

複雜模組（判定見 [architecture.md](../architecture.md) §3）。這份只寫規則、狀態轉換與驗收。

## 規則
- 觀眾兌換自訂的頻道點數獎勵時存一筆紀錄：觀眾、獎勵名稱、點數、觀眾輸入的文字、兌換時間、狀態。
- 同一個 Twitch 兌換 ID 只存一筆。資料庫的唯一限制也擋重複，不只靠程式判斷。
- 內部 ID 是 UUID v7；Twitch 兌換 ID 另存一欄。
- 狀態照 Twitch（EventSub `channel.channel_points_custom_reward_redemption.add` 與 `.update`）。
- 先收到狀態更新、才收到兌換本身時，更新事件本身就帶完整的兌換資料，直接用它建立紀錄；之後才到的兌換事件當成重複，不改紀錄。
- 重複收到的兌換事件不改紀錄。
- 模擬事件（`source=simulation`）不寫入紀錄。
- 寫入失敗（例如資料庫暫時忙碌）時，等 1、2、4 秒各重試一次，後面的事件照順序等著；仍失敗就寫進記錄檔，並把這次啟動以來的失敗筆數放在查詢結果的 `failed_writes`，兌換紀錄頁顯示提示。
- 模組停用期間收到的兌換直接丟棄，和其他記憶體事件一樣；已存的紀錄保留。
- 第一次存下一筆紀錄時（不論由兌換事件或狀態更新建立），在同一個交易裡經 outbox 發布 `RedemptionRecorded`，`occurredAt` 是兌換時間；重複的事件與狀態更新不再發布。
- 觀眾輸入的文字照原樣存，顯示時才跳脫。
- 時間存 UTC；Twitch 給的兌換時間讀不懂時，改用收到的時間。

## 狀態轉換
| 從 | 可以變成 |
|---|---|
| 未完成（`unfulfilled`） | 已完成（`fulfilled`）、已退還（`canceled`） |
| 不明（`unknown`） | 未完成、已完成、已退還 |
| 已完成 | 不能再變 |
| 已退還 | 不能再變；不會再變回有效 |

- 收到相同的狀態不算轉換，紀錄不變。
- 不合法的轉換被拒絕，紀錄保持原狀，並以 `redemption.invalid_transition` 寫進記錄檔（記 Twitch 兌換 ID 與前後狀態，不記觀眾輸入的文字）。
- Twitch 給的狀態值不認得時存成 `unknown`，不會讓程式出錯；之後收到已知狀態就照上表更新。已知狀態不會被 `unknown` 蓋掉。

## 驗收
- 同一個兌換 ID 重複收到，只有一筆紀錄。
- 狀態只能照上表轉換；已退還不能再變回有效；不合法的轉換被拒絕並寫進記錄檔。
- `unknown` 狀態照存，不出錯。
- 先收到狀態更新、才收到兌換本身時，資料不遺失，狀態不倒退。
- 模擬事件不產生紀錄；模組停用期間不產生紀錄。
- 查詢：可依兌換時間範圍、觀眾（登入名稱或顯示名稱的一部分）、獎勵名稱的一部分、狀態篩選，新的在前、分頁；沒有紀錄時顯示空白狀態；觀眾輸入的文字顯示時跳脫。
- 以上都有測試（Repository 用真 SQLite）。
