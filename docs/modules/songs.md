# 點歌

複雜模組（判定見 [architecture.md](../architecture.md) §3）：同一首歌只存一筆、點歌有不合法的狀態轉換、規則（每人上限、同一首冷卻）要在每一種點歌方式一致套用，用頻道點數點的歌還牽涉退還點數，出錯會直接傷到觀眾信任。這份只寫規則、狀態轉換與驗收。

模組 `songs`（功能清單的「點歌」：點歌、歌單、點歌規則三頁），預設開啟（不需要 Twitch 權限）。

## 歌單
- 一首歌：歌名（1–100 字）、歌手（可空，最多 100 字）、分類（可空，就是「未分類」）、YouTube 連結（可空，只接受 `youtube.com/watch?v=`、`youtu.be/` 網址）、上次唱的時間、被點次數。
- 同一首歌＝歌名與歌手正規化後相同（去頭尾空白、連續空白當一個、全形半形與英文大小寫視為相同）；資料庫的唯一限制也擋重複，不只靠程式判斷。
- 分類：名稱 1–30 字，不分大小寫不能重複；每個分類可以設定開不開放點歌。刪除分類時，裡面的歌移到「未分類」，不會被刪掉。未分類的歌可以點。
- 最多 5,000 首、100 個分類。
- 內部 ID 是 UUID v7；時間存 UTC。

## 匯入
- 在歌單頁選一個 Excel（`.xlsx`）或 CSV（UTF-8，有沒有 BOM 都可以）檔，最大 5 MB：管理 UI 把檔案送到 Host 預覽（會新增幾首、更新幾首、略過幾筆與原因），確認後才在同一個交易裡寫入。原始檔不會被修改。
- 第一列是標題，依標題找欄位：歌名（`歌名`、`title`、`song`，必填）、歌手（`歌手`、`artist`、`singer`）、分類（`分類`、`category`）、連結（`YouTube`、`連結`、`link`、`url`），不分大小寫；其他欄位忽略。Excel 的每個工作表都讀；沒有分類欄時，用工作表名稱當分類。
- 已有的歌（同一首）會更新：檔案裡有填的分類與連結蓋過原本的，空白的欄位不會把原本的值蓋成空的。新的分類一起建立，預設開放點歌。
- 略過並列出原因：沒有歌名、歌名或歌手太長、連結不是 YouTube 網址、和檔案裡前面的列是同一首、超過歌單上限。
- 同一份檔案匯入兩次，結果相同。

## 點歌
- 觀眾在聊天室打 `!點歌 文字`：指令名稱預設「點歌」，和其他功能共用指令表（`songs.request`），名稱只能屬於一個功能；誰能用沿用共用的四級。
- 比對：文字正規化後完全符合歌名，或是「歌名 歌手」「歌手 歌名」（打錯字的比對是 P4-3）。只有一首符合才排入；有幾首同名時請觀眾加上歌手。
- 只能點開放點歌的分類（或未分類）的歌。
- 同一首歌不會同時在待唱或正在唱兩次。
- 待唱最多 100 首。
- 每次排入，那首歌的被點次數加 1。
- 實況主可以在點歌頁手動點歌，幫誰點選填；手動點歌不受開放分類限制。
- 模擬事件（`source=simulation`）與演練不會排入；機器人自己的訊息不觸發。
- 模組停用時聊天的點歌直接忽略，已排的歌保留。

## 狀態轉換
| 從 | 可以變成 |
|---|---|
| 待唱（`queued`） | 正在唱（`singing`）、已移除（`removed`） |
| 正在唱 | 已唱（`sung`）、已移除 |
| 已唱 | 不能再變 |
| 已移除 | 不能再變 |

- 同時最多一首正在唱。「唱完了」把正在唱的標成已唱、更新那首歌的上次唱時間，再把待唱的第一首變成正在唱；沒有正在唱時，可以讓待唱的任一首開始唱。
- 不合法的轉換被拒絕，紀錄保持原狀。
- 待唱可以拖曳調整順序；移除或開始唱之後，其餘的順序不變。
- 已唱歌單照唱完的時間新的在前。

## 回覆
- 聊天機器人開著時，回覆每次點歌的結果：排入（第幾首）、找不到、有幾首同名、這首不開放點、已經在待唱、待唱已滿。文字在點歌規則頁改，可用 `{觀眾}`、`{歌名}`、`{歌手}`、`{順位}`、`{輸入}`，只有固定替換。
- 回覆經由聊天機器人的佇列送出，照它「發言」的規則（不觸發自己、限速、模擬事件不送）；聊天機器人關閉時不回覆，點歌照常排入。
- 觀眾輸入的文字與歌名只當文字顯示與送出，不解讀成變數。

## 資料
- 歌、分類與點歌紀錄存在模組自己的資料表；回覆文字存在 `settings.json` 的 `songs`；指令名稱與誰能用在共用指令表。

## 驗收
- 同一首歌只存一筆（資料庫也擋）；刪除分類不刪歌；匯入的預覽、去重、略過原因都看得到，空白欄不覆蓋既有值，同一份檔案匯入兩次結果相同。
- 點歌照比對、開放分類、不重複、上限排入；手動點歌不受開放分類限制；被點次數照排入次數增加。
- 狀態只能照上表轉換；同時最多一首正在唱；唱完更新上次唱。
- 模擬事件、演練與機器人自己的訊息不會排入；聊天機器人關閉時不回覆但照常排入。
- 以上都有測試（Repository 用真 SQLite）。
