# 範圍

## 定位
本機優先的 Twitch 實況互動工具，只做實際直播用得到的功能。目標是取代目前依賴的第三方聊天室、特效與 SO 服務。

## 責任邊界
- Twitch 管頻道點數的餘額、扣點與退款；本工具只接收兌換事件、存紀錄、觸發本機動作。
- 本機兌換紀錄可能因離線或漏接而不完整，不宣稱與 Twitch 完全一致。
- Twitch、OBS 仍是必要的外部服務；「本機優先」不等於完全離線。
- SO 播放的影片仍來自 Twitch，來源失效時無法播放。

## 目標
以原型的完整功能為目標，分 6 個群組：首頁、點歌、聊天、互動、畫面與聲音、觀眾。依下方的階段做，每完成一個階段就實際直播試用，並發一個版本。

## 已完成的基礎
這些都已完成，之後的階段在上面繼續做。

| # | 切片 | 完成時看得到什麼 |
|---|---|---|
| 0 | Walking skeleton | 首次設定引導註冊 Twitch app 並填入 Client ID，用 Device Code Flow 登入，Token 存 keyring 並自動刷新；Tauri 視窗啟動本機 Host（port 被佔用時提示並可修改）；OBS Browser Source 載入本機網址並顯示 Twitch 聊天；[decisions.md](decisions.md) 標為「Skeleton 就建立」的基礎都已就位 |
| 1 | 自訂聊天室 | 選擇內建樣板後 OBS 立即套用；斷線時畫面顯示狀態並自動重連；管理 UI 顯示 Twitch 與 OBS（OBS WebSocket）連線狀態 |
| 2 | 追隨、訂閱、小奇點、揪團 | 追隨、新訂閱、續訂、送禮訂閱、小奇點、揪團觸發 Overlay 動畫與音效，同時來多則時依序播，同一次送禮訂閱只播一則；可從內建樣板挑選；可用事件模擬器測試，不用等真的有人追隨 |
| 3 | 兌換紀錄 | 收到頻道點數兌換就存檔（依兌換 ID 去重），UI 可查詢；第一個複雜模組 |
| 4 | 打卡簽到 | 觀眾可用頻道點數兌換、聊天室指令打卡，實況主可在 UI 手動登記或補登；同一觀眾同一營運日只算一次，依實況主設定的時區切日；集點卡依累計次數顯示；可匯入舊打卡資料（JSON 格式，見 [modules/checkin.md](modules/checkin.md)；匯入前預覽、去重、不破壞原檔） |
| 5 | 音效管理 | 匯入本機音效檔（MP3、WAV、OGG），指定特效、打卡與頻道點數獎勵各播哪個音效；音效都在 OBS 播放，兌換的音效用另一個 OBS 網址依序播放 |
| 6 | 備份還原 | 一鍵匯出／匯入設定與紀錄，匯入後資料完整 |
| 7 | Windows 可攜版 | 另一台電腦解壓縮即可使用；zip 附第三方授權清單，以及 SmartScreen 與「解除封鎖」的操作說明；有新版時管理 UI 會提示，解壓縮覆蓋舊資料夾就能更新，資料不受影響 |

## 階段
每個階段只依賴前面的階段；同一階段內的順序依直播需要調整。細項在 GitHub Issues（label `phase-0`～`phase-9`），技術面的後續項目見 [decisions.md](decisions.md)。

| # | 內容 |
|---|---|
| 0 | 畫面全部擺上：上方群組分頁、所有頁面（還沒做的在分頁、首頁磚與功能清單裡是灰色、不能點）、功能開關頁、常駐聊天室、自訂分頁、文字大小 |
| 1 | 共用基礎：Twitch 事件欄位擴充、OBS 控制與事件、呈現佇列、直播狀態與場次、活動紀錄、觀眾身分、Overlay 連線追蹤 |
| 2 | 只用共用基礎的功能：場景與背景音樂、首頁統計、事件流、聊天紀錄與顯示、計數器、畫面工具、卡片編輯器、演練等 |
| 3 | 依功能申請權限，以及要寫入 Twitch 的功能：聊天機器人、頻道點數獎勵管理、直播資訊、投票與預測等 |
| 4 | 點歌（可選擇串接雷虎練唱台） |
| 5 | SO 與影片、感謝名單、揪團 |
| 6 | 模式 |
| 7 | 觀眾進階、個人徽章、聊天室管理、聊天過濾 |
| 8 | 虛擬形象（VTuber Plus、VSeeFace）、即時字幕、文字轉語音 |
| 9 | 快捷鍵、置頂聊天室、設定檔、機器人帳號、主題與語言 |

**其他想法：** 記在 backlog，不排程，不寫規格。

## 不做
通用規則引擎、Linux、原生手機 App、雲端服務、抽獎、OneComme 串接。

## 加新功能前問三題
1. 它解決我直播時已經遇到的問題嗎？
2. 最小做到哪裡就能拿去直播用？
3. 它會拖慢目前正在做的階段嗎？
