# Technical decisions

Everything below is decided (2026-11-12). Change an item only when it causes a real problem, and add one line to the "Change log" at the bottom when you do. Layer and module rules are in [architecture.en.md](architecture.en.md).

## Choices
| Item | Decision |
|---|---|
| Architecture | DDD + Clean Architecture, implemented as a Modular Monolith |
| DDD scope | Tactical patterns only in complex modules; criteria in architecture.en.md |
| Module layout | Cargo workspace, one crate per module, with `domain`/`application`/`infrastructure` folders inside; thin modules keep all three layers too |
| Module communication | Public application service traits + domain events (through the outbox); integration events such as chat are only broadcast in memory |
| Data ownership | One SQLite file, tables owned by modules, no cross-module joins; write transactions always use `BEGIN IMMEDIATE` (or a single writer connection) |
| Model separation | Complex modules: Domain/DTO/Row/Event fully separate; thin modules: only DTOs split out |
| Backend | Rust + Axum |
| Desktop/frontend | Tauri 2 + Vue 3 + TypeScript |
| Database access | SQLite + SQLx, schema managed by migrations |
| Communication | All clients use HTTP (commands/queries) + WebSocket (events), with snapshot + resync on reconnect; the exception is a few Tauri IPC commands (see architecture.en.md) |
| API contract | Code-first: generate OpenAPI and TS types from Rust |
| Event format | Envelope from the first version: `id`, `type`, `version`, `seq`, `occurredAt`, `source` |
| Host lifecycle | Same process as Tauri; closing the window hides it to the system tray; single instance |
| Architecture enforcement | Crate dependencies + architecture tests (run in CI) |
| Testing | First version: Unit + Integration (real SQLite) + Contract (generated files up to date) + UI E2E (Playwright + Chromium) |
| CI | GitHub Actions, built with the skeleton, Windows only, runs on PRs only; also runs `cargo clippy --features tauri/custom-protocol` to check code compiled only in release; UI E2E is a separate workflow, run by hand and before a release |
| Releases | Always built with `tauri build`; never distribute builds without `tauri/custom-protocol` |
| Overlay customization | First version allows HTML/CSS templates only; the chat and alert templates are picked from built-in styles in the admin UI (alerts have no folder template), with no in-app editing, uploads or font and color adjustments; the admin UI has no entry for the chat's custom template in the data folder (`custom`); it is set by hand in `settings.json` and takes effect after a restart |
| Platforms | Windows first; macOS to be evaluated later; Linux not supported |
| Decision records | This file + architecture.en.md; no ADRs |
| Document structure | README + four files under `docs/` (scope/architecture/decisions/dev); complex modules also get `docs/modules/<module>.md` |
| Document language | README and `docs/` are bilingual: Traditional Chinese is authoritative, the English version is the matching `.en.md`; write Chinese only while working and generate English before committing docs; sync is checked by hash (rules in dev.en.md). Archived documents are not translated |
| Code language conventions | Identifiers, comments, API/DB fields and error codes are always English |
| Commits | English Conventional Commits, e.g. `feat(checkin): add daily check-in rule` |
| Backlog | GitHub Issues (labels by phase, `phase-0` to `phase-9`, plus `later` and `bug`), not in documents |
| AI guide | `AGENTS.md` (English); `CLAUDE.md` only references `AGENTS.md` |
| Remote repo | GitHub public |
| License | MIT (`LICENSE`) |
| Dependency licenses | Rust (`cargo-deny`) allowlist: MIT, Apache-2.0, BSD-2/3-Clause, ISC, Zlib, Unicode-3.0, MPL-2.0, CDLA-Permissive-2.0. The frontend has its own list and checks only dependencies shipped in the build: the above plus 0BSD, CC0-1.0, CC-BY-4.0, BlueOak-1.0.0, Python-2.0. GPL/LGPL/AGPL always blocked |
| Third-party license list | `cargo-about` (Rust) + `pnpm licenses` (frontend) + `assets/CREDITS.md` combined into `THIRD_PARTY_LICENSES`, generated only by release builds and never committed; shipped in the portable zip and the settings page's About section |
| Bundled assets | Only redistributable assets (CC0, CC-BY, OFL for fonts, etc.), with source and license recorded in `assets/CREDITS.md`; user-imported assets never go into the repo |
| Branches | Default `main`; work happens on short-lived branches, rebase-merged by PR after CI passes (the only merge method the repo allows), so `main` stays one straight line; exactly one commit per issue, and one PR may hold several independent issues from the same stage |
| Line endings | `.gitattributes`: LF everywhere; CRLF for `.ps1`/`.bat`/`.cmd`; images, sounds, videos and fonts marked binary |
| Git hooks | lefthook (`lefthook.yml`) |
| Commit identity | GitHub noreply email, set for this repo only |
| Twitch OAuth | Device Code Flow (public client, no client secret needed) |
| Twitch app | Each user registers their own app (Public client; enter `http://localhost` for the Redirect URL the form requires) in the Twitch Console; first-run setup guides them through registering the app and entering the Client ID, which is stored in settings; no shared built-in Client ID |
| Twitch scopes | Request the base scopes at first login: `user:read:chat`, `moderator:read:followers`, `channel:read:subscriptions`, `channel:read:redemptions`, `bits:read`; scopes other features need are requested the first time the user turns that feature on (first explaining which scopes to grant, then signing in again to grant them); when a stored sign-in lacks any base scope, the admin UI asks to sign in again once; until then chat keeps working and events needing a missing scope are not subscribed |
| Token refresh | Only one refresh at a time; write the new refresh token to keyring before using the new access token, and if that write fails, keep the new tokens in memory and retry the write (if the app closes before the retry succeeds, the next start requires logging in again); if refresh fails (400/401), restart the Device Code Flow and show "login required" in the UI. Public-client refresh tokens expire after 30 days, so long inactivity requires logging in again |
| Admin window | Loads the Host URL `http://127.0.0.1:<port>/admin` (same origin as the API, no CORS); may only navigate to `/admin` paths, and opening new windows is always denied; `/admin` sends a strict CSP; the Twitch verification page is opened in the system browser by a Rust command; zoom hotkeys enabled (`zoom_hotkeys_enabled(true)`: `Ctrl` with `+`/`-`, `Ctrl` with the mouse wheel); minimum content area 360×480 (width×height) |
| Tauri IPC permissions | App commands declared with `AppManifest`; three capabilities: small port-change page (`port` window only), admin window dev (local, `admin` window only), admin window release build (remote, created at startup for the actual port, URLs limited to the Host origin, path restricted by `on_navigation`); "dev" means the `tauri/custom-protocol` feature is off (`cfg(dev)`): `tauri build` turns it on and is the only distributable build; `tauri dev` and plain cargo commands are dev; `apps/desktop` decides and tells the Host through runtime configuration |
| Local API security | Per-launch random admin token, delivered to the admin window over an IPC command and kept in memory only; Host header allowlist; Origin checks (`Origin: null` rejected); overlays are read-only, carry no token, and every response on overlay and template paths sends `script-src 'self'; object-src 'none'`; the template directory serves only non-script files with `nosniff`; template previews go in a sandboxed iframe and receive data via `postMessage` (details in architecture.en.md) |
| Port | Fixed default port `47810`. If the configured port is occupied, do not change it automatically; instead, open the small port-change page for the user to choose another port and retry. On the first launch of a data directory, if the default port is occupied, automatically select and save an available port |
| Data directory | Each data directory serves as an application data unit, identified by its `instance-id`: the one given by `--data-dir`, otherwise the `data` folder next to the executable; settings, logs, cache and WebView2 data all live in it; only one instance may run per data directory, different data directories can run side by side; Twitch sign-in is per data directory; an unwritable data directory shows an error and exits (details in architecture.en.md §6) |
| Frontend files | Admin UI and overlays embedded into the executable with `rust-embed`, served by the Host; the small port-change page serves as Tauri's `frontendDist`; `app.windows: []`, with all windows created from Rust (in `setup` or after a successful port retry); the build `assets/` directory and the template paths (`/templates`, built-in templates included) send `Access-Control-Allow-Origin: *` so the preview iframe can load them |
| Dev mode | Vite dev server + proxy (`/api`, `/ws`, `/templates`, `/sounds`, `/music`, `/media`, `/checkin`, target `http://127.0.0.1:<port>`, with the port read from the dev data folder's `settings.json` on every request, `changeOrigin: true` and `ws: true`) to the Host; Tauri `build.devUrl` set to the Vite URL, Vite `server.strictPort: true`; Vite sends the same CSP as the Host (the `/admin` or overlay one); in dev mode Vite allows the `null` origin on everything except `/api`, `/ws`, `/templates`, `/sounds`, `/music`, `/media` and `/checkin` (`server.cors: false` + middleware), with Cargo's `target` folder added to `server.fs.deny` (the dev data folder is inside it and the `null` origin must not read it); dev mode adds the Vite origin to the Origin allowlist |
| Admin UI layout | Sticky top bar + group tabs across the top, no sidebar. The top bar holds the app name, the Twitch and OBS status (on home they open the connections drawer; on other pages they navigate to the corresponding section of settings), 「模擬事件」 (a dialog that sends one test event to each of the chat, alert, sound and check-in card overlays and shows whether that overlay is connected in OBS; rows of features turned off cannot send), and the settings button, and stays visible while scrolling. Navigation has three levels: groups in the bar; a group's categories in the second row (home and songs have no categories, so the second row lists their pages), where a category opens the page last seen in it; when a category has several pages, they are a row of page tabs under the page title; groups that do not fit go into "More", and there is no "More" when they all fit; settings is not a tab. The user can choose which groups are pinned in the tab bar, their order (by dragging or with buttons), and whether the bar sits on top or at the bottom (at the bottom it stays at the bottom of the window, with the group's second row moved down above it; always at the bottom below 600px, with notifications shown just above it, the category row scrolling sideways edge to edge, and home's before/live/after choice kept on one row that scrolls sideways when it does not fit); groups not pinned are in "More"; when nothing needs "More", "Edit tabs" sits in the bar itself; all this is stored in `settings.json` and included in backup and restore. The docked chat panel is open by default (closing it is remembered) and the chat button in the top bar opens and closes it: on wide windows it is docked on the right or the left (chosen in the panel's display menu; resizable, collapsible; pages keep at least 720px, and on a window too narrow for that the chat panel is only shown narrower, with its saved width unchanged), and on windows narrower than 1000px it slides in from the right; whether it is open, its width and its side are stored in `settings.json` and included in backup and restore; while it is docked, home does not show the chat tile; on the chat log page it steps aside and comes back after, without changing its saved open state. Pages use the full window width (up to 120rem, minus the docked chat panel), while forms and running text stay within 48rem. The layout follows the width of the content area, not the window: below 45rem each table row takes two lines without column names, and below 28rem buttons in a table keep only their icon; each settings section follows the width of its own column; a segmented choice that does not fit wraps whole options. Home is still feature tiles + drawer (each tile has a colored icon, its name, a big value with its unit, and a one-line summary; small tiles are all the same height, and one with nothing to count shows 「—」 in place of the number; the counter, sound and break card tiles act in place of the summary line (−1/+1 for the first counter, the first three sounds of the list, covering with the break card), and the rest of the tile still opens the drawer; a feature not built yet is a grey tile that does nothing, not on home by default but listed among the hidden tiles in 「編輯首頁」 to add back; unbuilt pages are grey and inert in the tabs, categories, page tabs, 「更多」 menu and feature list too, their URLs lead home, and a group tab is grey while the group has no page that is built and on; pages of a feature turned off are not shown and cannot be opened by URL or Back either, which go to the first open page of the group instead, or home when the whole group is off; settings › features lists the features by category; the settings menu lists the groups under features to jump to; each group can turn all its built features on or off, confirmed once with everything it takes along, check-in's pause or close asked first, and nothing changes when any of it is cancelled; at the top, 「使用 Twitch」 and 「使用 OBS」 switches: turning one off lists the features on that need it (directly or through what they require, such as the singing booth needing song requests), and once confirmed they go off and are locked, their tabs, tiles, top bar light and not-connected notices fold away, and the features turned off are remembered (`services` in `settings.json`, `GET`/`PUT /api/admin/services`) and turned on again when the service is used again), and each feature's full page is at `/admin/<feature>`, with a top row of 「← 回首頁」, the tile's icon and the title, and at its right end the page's state (such as the scene on air) and the OBS status link (「在 OBS：N 個場景，含／不含直播中」, 「OBS 裡有 2 個」, 「還沒加入 OBS」; it opens the OBS sources page), which moves below the title when it is too long; on windows at least 601px wide and 560px tall, this row and the page tabs stay pinned under the top bar while scrolling. When Twitch or OBS, needed by the page's feature, is down (not while loading, and not when the admin UI loses the Host itself), one notice per service with 「去連線」 shows under the page tabs, and the feature's row in settings › features is tagged 「Twitch 沒連上」 or 「OBS 沒連上」; the page does not say it again. Only a page with one overlay puts it in the header; with several overlays (such as the counter and the marathon timer), each sits in its own section; home's drawers and the pre-stream checks use the same link. The drawer has four sections in order, "Actions", "Now", "Frequently changed settings" and "Open full page"; sections a feature does not use are omitted; the drawer's title row stays put while only its content scrolls. Tiles sit in one grid; with "Edit home" the user reorders, hides and adds back tiles right on the grid (an order saved while tiles came in the "Live" and "Features" groups is converted once, in the order it was shown, the first time the Host reads it); 開播前檢查, 本場直播, 本場摘要 and 待處理 are blocks in the grid too, wider than tiles, with their content right on home; 開播前, 直播中 and 下播後 each have their own order, switched with the stream state, and the list and order are stored in `settings.json` ("never saved" must be distinguishable from "emptied") and included in backup and restore |
| Drawer component | Custom: Vue `Teleport` moves the same content between a side-by-side `<aside>` (window > 1000px) and a modal native `<dialog>` (≤ 1000px) without remounting; PrimeVue Drawer is not used (overlay mode only); PrimeVue overlay components inside the drawer set `appendTo="self"`; before moving, record the focused element and the `scrollTop` of each scroll container, and restore them afterwards |

## Packages
| Purpose | Package |
|---|---|
| Domain event dispatch | Custom outbox dispatcher: events are written to the outbox table in the same transaction as the business data, dispatched in the background with delivery state tracked per subscriber, retried on failure and shown in the UI, and resent after a restart; when disabling a module the streamer chooses "pause" (events kept and delivered after re-enabling) or "off" (after a warning, events from the disabled period skipped); events past the retry cap move to a dead-letter queue; fully delivered events are cleaned up periodically; subscribers deduplicate by event ID with an inbox table (details in architecture.en.md) |
| Migrations | Each module has its own folder, files use timestamp versions (globally unique); `host` merges them into a single SQLx Migrator at startup; rules and dev command in architecture.en.md |
| Error handling | `thiserror` (domain/application, mapped to error codes) + `anyhow` (only in the host composition root and startup); error codes use `<area>.<reason>` (e.g. `twitch.sign_in_required`), the API returns `{"code": …}`, the UI shows the message for the resource key `errors.<code>`, and logs use a `code` field too |
| Time | `chrono` + `chrono-tz` |
| IDs | UUID v7 (`uuid`); external IDs (e.g. Twitch redemption IDs) stored in separate columns |
| Randomness | `fastrand`: the background music's shuffled order; never used for anything security-related |
| Twitch | Hand-written serde types (only the Helix, OAuth and EventSub fields we use) + custom EventSub WebSocket connection (`tokio-tungstenite`); chat via EventSub `channel.chat.message`, and the follow, sub, Bits and raid alerts via EventSub too (subscription list in architecture.en.md) |
| Outgoing HTTPS | `hyper-util` + `hyper-rustls` + `rustls` (`ring`) + `rustls-platform-verifier`: certificates checked against the Windows store; EventSub `wss://` shares the same TLS config |
| OBS | `obws`; connected, reads the state of scenes, items, inputs and outputs, and can switch scenes, show or hide items and lock items |
| Credentials | `keyring-core` + `windows-native-keyring-store` (the combination keyring 4 recommends apps link directly), compiled on Windows only; never falls back to a mock store |
| Secrets | `secrecy`: tokens are wrapped in `SecretString` and never logged |
| Logging | `tracing` + `tracing-subscriber` (JSON) + `tracing-appender` (daily rotation with a 14-day retention period); written to the data directory's `logs/`, level adjustable with `RUST_LOG`; output-layer masking is only a backup |
| Embedded frontend | `rust-embed` (with `debug-embed`) |
| Backup files | `zip` (deflate only: `flate2` + `zlib-rs`) + `sha2`; format in architecture.en.md §6 "Backup files" |
| Performance monitor | `sysinfo` (MIT, `system` only): CPU and memory of this computer and of this app's process |
| Image sizes | `image` (MIT/Apache-2.0, PNG, JPEG, GIF and WebP only) to resize; `oxipng` (MIT, default features off) to compress PNGs losslessly; `color_quant` (MIT) to reduce to 256 colors. Never `libimagequant` (GPL-3) |
| OpenAPI | `utoipa` |
| Frontend API types | `openapi-typescript` + `openapi-fetch`; WS event types also live in OpenAPI components |
| Architecture tests | Custom Rust test: `cargo_metadata` checks crate dependencies and scans `domain/` for any occurrence of `sqlx`/`axum` (including derives and full paths) |
| Frontend structure | `apps/web` as one Vite project with multiple entries (admin UI + each overlay + small port-change page); overlays do not load the UI component library |
| UI component library | PrimeVue 4.5.5 (`@primeuix/themes` 2.0.3), Aura preset fixed to dark; `definePreset` overrides the primary and surface palettes; exact versions (no `^`/`~`), no upgrade to PrimeVue 5 (now under a proprietary license) |
| Icons | PrimeIcons 7.0.0 (exact version); no upgrade to 8 (now under a proprietary license) |
| Frontend routing | vue-router (history mode, base `/admin/`); the dev admin window loads `admin/` (not `admin/index.html`, which would not match any route), and Vite adds a deep-path fallback |
| Frontend state | Pinia |
| Frontend tests | Vitest + Vue Test Utils; UI E2E with Playwright (`@playwright/test`, Apache-2.0, dev dependency only) + Chromium (the same engine as WebView2) |
| Frontend lint | ESLint (flat config + `eslint-plugin-vue` + `@vue/eslint-config-typescript`), correctness-focused rules only; no formatting or stylistic rules |
| UI strings | `vue-i18n` + `@intlify/unplugin-vue-i18n`: resource files are precompiled at build time, so no `unsafe-eval` at run time |
| Single instance | `tauri-plugin-single-instance` |
| Opening external URLs | `tauri-plugin-opener`, called only from Rust, opens external URLs in the system browser: each external URL the admin window needs (Twitch verification page, new-version download page, etc.) gets its own command with a hard-coded URL and no parameters; when WebView2 is missing, the startup flow opens Microsoft's download page directly. No generic command that takes a URL parameter, and no window is granted opener plugin permissions |
| Distribution | Portable zip only (`tauri build --no-bundle` produces the executable, then it is packed into a zip); no installer. The app is not code-signed; the documentation includes the SmartScreen "Run anyway" and zip "Unblock" steps. Updates: release builds check GitHub Releases for the latest stable release at startup and every 24 hours after (`releases/latest`, which excludes drafts and pre-releases; a fixed User-Agent, no user data, a timeout, and no notice or error on failure); if it is newer than the running version, the admin UI home page shows a notice with a button that opens the download page (a hard-coded-URL command; no URL from the response is ever used); the user extracts the new zip into the existing application folder. "Not this one" is stored in `settings.json`, and only a newer release shows the notice again; the check can be turned off in Settings → General, and then no request is made. The zip never contains a `data` folder, so extracting over the old folder does not overwrite or modify existing data. Upgrades only: an older build refuses to open newer data |
| WebView2 | Uses the system's Evergreen WebView2 Runtime (built into Windows 11); detected at startup, and if missing, an explanation is shown and Microsoft's download page opens while the Host, overlays and tray keep running; no fixed-version runtime is bundled |
| Dev tools | `@tauri-apps/cli` and `lefthook` are pnpm devDependencies, version-locked by the lockfile, with no global install; sccache is optional, installed and configured through environment variables by each developer, never in the repo |
| Package management | Node 24 LTS (in `.nvmrc`); install pnpm once with `npm i -g pnpm`, after which it switches versions according to `packageManager` in `package.json`; no Corepack |

## Change log
| Date | What changed | Why |
|---|---|---|
| 2026-11-13 | Node 26 LTS changed to Node 24 LTS | Already installed on the dev machine and supported until 2028-04; pnpm manages its own version without Corepack, so 26's advantages do not matter for this project |
| 2026-11-13 | Tauri CLI and lefthook changed to pnpm devDependencies | Versions locked by the lockfile, with no system changes |
| 2026-11-13 | Twitch types changed from the `twitch_api` crate to hand-written serde types | The MVP uses only a few events; drops a large dependency tree and gives full control over fields and values such as `unknown` |
| 2026-11-13 | Data storage changed to the "data directory" model (`--data-dir`, portable copies, one instance per data directory) | Testing and upgrades need side-by-side copies; NSIS registers only one install per product, so portable copies and `--data-dir` are used instead |
| 2026-11-13 | SQLite and the automatic backup before migrations moved to the redemption records slice | The skeleton has no tables yet; the backup is then tested with real data |
| 2026-11-13 | ESLint chosen for frontend lint | Provides the most comprehensive support for Vue SFCs |
| 2026-11-13 | Error codes unified as `<area>.<reason>` | The API, UI resource keys and logs share one code |
| 2026-11-13 | The core crate's package name is `toolkit-core` | `core` collides with Rust's built-in crate |
| 2026-11-13 | The MVP ships only a Windows portable package, no installer; data always sits next to the executable (or in `--data-dir`) | No code-signing certificate will be bought, and unsigned installers are more likely to be blocked by antivirus and SmartScreen; a portable package also fits the data directory model |
| 2026-11-13 | The app is not code-signed | No certificate will be bought; Azure Artifact Signing is open to individuals only in the USA and Canada; SmartScreen warnings are accepted, and the documentation includes the steps |
| 2026-11-13 | Missing WebView2 is detected and the user is guided to install it | Built into Windows 11 and present on the vast majority of Windows 10 PCs; a fixed-version runtime gets no automatic security updates, so none is bundled |
| 2026-11-13 | The portable package uses "new-version notice + manual replacement"; auto-update moves to after the MVP | The Tauri updater supports only installers on Windows; the app must never replace itself during a stream, and manual replacement is the safest and simplest |
| 2026-11-14 | Added admin UI layout, drawer component, visual style, frontend routing and icons; UI component library set to the Aura preset (fixed dark, palettes overridden with `definePreset`); opening external URLs limited to hard-coded-URL commands; admin window gets zoom hotkeys and a minimum size | UI/UX planning settled: sidebar + card grid looked too much like a generic back-office admin system, so feature tiles are used; PrimeVue Drawer cannot sit side by side, so the drawer is custom; a command that accepts a URL parameter would let an injected script in the admin window open any URL or custom protocol; zoom hotkeys let users enlarge content (WCAG 1.4.4) |
| 2026-11-14 | PrimeVue pinned to 4.5.5, `@primeuix/themes` to 2.0.3, PrimeIcons to 7.0.0 (exact versions) | PrimeVue 5, `@primeuix/themes` 3 and PrimeIcons 8 moved to the proprietary PrimeUI License (license key required, source may not be extracted), which is not on the allowlist; these are the last MIT versions. v4 gets no further fixes; revisit if a security issue appears |
| 2026-11-14 | In dev mode, the proxy port is read on every request from the `settings.json` of the dev data folder (`target\debug\data\`); Vite's `server.fs.deny` also covers Cargo's `target` folder | Vite starts before the app, a data folder's first run may switch ports automatically, and the port page may save a new port, so reading it once at startup can be wrong; the `null` origin can read the files Vite serves, and the dev data folder (settings, logs, WebView2 data) is inside `target` |
| 2026-11-15 | UI E2E moved from after the MVP into the MVP, with Playwright + Chromium; the manual checklist in dev.md keeps only what automation cannot do | The manual drawer, dialog and layout checks had to be repeated for every slice, and jsdom cannot test them; Chromium is the same engine as WebView2, so the results hold. Real Twitch/OBS connections, the native window ✕, the system tray and actual OBS visuals stay manual |
